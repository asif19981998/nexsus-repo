# ইউজিসি ইন্টার্নশিপ প্রোগ্রাম — নির্মাণ পরিকল্পনা

এটি [01-requirements.bn.md](01-requirements.bn.md)-এর সঙ্গী দলিল। এখানে বলা হয়েছে প্রোগ্রামটি **বাস্তব সিস্টেম হিসেবে কীভাবে তৈরি**: ডেটাবেস, ব্যাকএন্ড API ও ফ্রন্টএন্ড, এবং এরপর কী আসবে।

> **অবস্থা (২৪ নভেম্বর ২০২৬)।** এই পরিকল্পনার প্রথম সংস্করণে শুধু ব্রাউজারে চলা একটি প্রোটোটাইপের (Zustand + `localStorage`) কথা ছিল। সেই প্রোটোটাইপ **মুছে ফেলা হয়েছে**। প্রোগ্রামটি এখন ASP.NET Core API-র পেছনে SQL Server ডেটাবেসে চলে, আর Next.js ফ্রন্টএন্ড শুধু সেই API ডাকে।

## ১. Nexus-এর বাকি অংশের সঙ্গে মিল

| Nexus-এ আজ | ইউজিসি ইন্টার্নশিপ নীতিমালা | সিদ্ধান্ত |
| --- | --- | --- |
| কোম্পানি ইন্টার্ন নেয়; ইউজিসি বৃত্তি **সহ-অর্থায়ন** করে ৫০/৫০ (`funding`, `/ugc/co-funding`)। এই অংশগুলো এখনো শুধু ব্রাউজারের প্রোটোটাইপ। | ইউজিসি নিজেই ইন্টার্ন নেয় এবং নিজের বাজেট থেকে ১০০% দেয় (cl.10, cl.18)। | নিজস্ব ডেটাবেস, API ও পর্দাসহ **আলাদা মডিউল**। `opportunities` → `applications` → `funding` শৃঙ্খল পুনর্ব্যবহার নয়। |
| ছয়টি প্রোটোটাইপ পোর্টাল (student, faculty, organization, university admin, UGC, helpdesk), নকল লগইন। | আবেদনকারী, ইউজিসি প্রশাসন, বিভাগ, হিসাব শাখা। | নিজস্ব লগইন ও ভূমিকা: **Admin**, **Mentor**, **Student**। ব্যবহারকারী ডেটাবেসে থাকে। |
| `localStorage`-এ নকল অডিট ও নোটিফিকেশন। | প্রতিটি ধাপ অনুসরণযোগ্য হতে হবে (cl.16, FR-X1)। | বাস্তব `AuditLogs` ও `Notifications` টেবিল, পরিবর্তনের একই ট্রানজ্যাকশনে লেখা হয়। |

## ২. কোথায় দেখা যাবে

```
লগইন               /login
শিক্ষার্থী          /internship/programme       (Programme, My application, My internship)
Admin / Mentor     /internship/manage          (Overview, Batches, Applications, Interns, Allowance)
Admin              /internship/users           (ব্যবহারকারী তৈরি, ভূমিকা, পাসওয়ার্ড রিসেট, নিষ্ক্রিয়)
সবাই               /internship/notifications
API                http://localhost:5080/api/v1   (Swagger: /swagger)
```

লগইনের পর ব্যবহারকারী তার অনুমতি অনুযায়ী প্রথম খোলা পর্দায় যায়। কোনো মেনু বা ট্যাব কেবল সেই ভূমিকাই দেখে, যার সেই অনুমতি আছে।

## ৩. আর্কিটেকচার

```
backend/                                  ASP.NET Core 8, EF Core, SQL Server
├─ Nexus.Domain           এন্টিটি ও enum (Batch, Application, Internship, Attendance, Bill, Report,
│                         Evaluation, Department, InternshipPolicy, User, Role, Permission …)
├─ Nexus.Application      সার্ভিস, DTO, অনুমতির তালিকা, নীতিমালার নিয়ম (Rules/InternshipRules.cs)
├─ Nexus.Infrastructure   DbContext, কনফিগারেশন, রিপোজিটরি, মাইগ্রেশন, সিডার, JWT
├─ Nexus.API              কন্ট্রোলার, [HasPermission] অনুমোদন, Program.cs
└─ Nexus.BuildingBlocks   exception → ProblemDetails (400/401/403/404/409)

nexus-main - Copy/src/                    Next.js (App Router), JavaScript
├─ lib/api.js                             fetch ক্লায়েন্ট: JWT পাঠায়, 401 হলে লগআউট
├─ hooks/useApi.js                        useApiQuery, useAction, useSession().can(permission)
├─ store/useAuthStore.js                  টোকেন ও লগইন করা ব্যবহারকারী (ভূমিকা + অনুমতি কোড)
├─ lib/internshipPermissions.js           অনুমতি কোড (Permissions.cs-এর প্রতিচ্ছবি), ট্যাব, মেনু
├─ components/layout/InternshipShell.js   পোর্টাল ফ্রেম; /auth/me থেকে ব্যবহারকারী হালনাগাদ করে
└─ app/(internship)/internship/           programme/, manage/, users/, notifications/
```

নির্মাণের নিয়ম:

1. **নীতিমালার সংখ্যা ডেটাবেসে থাকে।** `InternshipPolicy`-র একটি সারিতে আছে ২০ আসন, বছরে ২ ব্যাচ, ৩–৬ মাস, ২০,০০০ টাকা, ৮০% উপস্থিতি, ১৫ কর্মদিবস ও ফর্মের সীমা। `Departments`, `EvaluationCriteria` ও `GradeBands`-এ তালিকাগুলো থাকে। পর্দাগুলো এগুলো `GET /internship/setup` থেকে পড়ে। নিয়ম বদলাতে সারিটি বদলালেই হয়, কোড বদলাতে হয় না।
2. **নিয়ম সার্ভারে প্রয়োগ হয়।** সব হিসাব (যোগ্যতা, কর্মদিবস, উপস্থিতি %, বিল, কর্তন, শেষ মাসের ভাতা আটকে রাখা, গ্রেড) `InternshipRules.cs`-এ। ফ্রন্টএন্ড শুধু ফল দেখায়, নিজে হিসাব করে না। (একমাত্র ব্যতিক্রম মেন্টরের মাসিক মূল্যায়ন ফর্মে নিট অঙ্কের পূর্বাভাস; সংরক্ষিত অঙ্ক সার্ভার হিসাব করে।)
3. **অনুমতি ডেটাবেস থেকে আসে।** `RolePermissions` টেবিল ভূমিকার সঙ্গে অনুমতি কোড যুক্ত করে। API প্রতিটি অনুরোধে এটি দেখে, তাই পরিবর্তন সঙ্গে সঙ্গে কার্যকর হয়, আবার লগইন করতে হয় না। ফ্রন্টএন্ড শুধু যা করা যাবে না তা লুকায়।
4. **এক পরিবর্তন, এক ট্রানজ্যাকশন।** অবস্থা পরিবর্তন, তার ইতিহাসের সারি, অডিট ও নোটিফিকেশন একসঙ্গে সংরক্ষিত হয়, নয়তো কোনোটিই হয় না।
5. **স্কিমা বদলায় EF Core মাইগ্রেশনের মাধ্যমে।** API চালু হওয়ার সময় বাকি মাইগ্রেশন প্রয়োগ করে।

## ৪. ভূমিকা

| ভূমিকা | যা করতে পারে (ডিফল্ট অনুমতি) |
| --- | --- |
| **Student** | প্রোগ্রাম ও যোগ্যতা দেখা, আবেদন ও প্রত্যাহার, নিজের আবেদন ও ইন্টার্নশিপ দেখা, check in/out, ছুটির আবেদন, মাসিক প্রতিবেদন (ওই মাসের বিল) জমা, চূড়ান্ত প্রতিবেদন জমা, পরিশোধ স্লিপ দেখা। |
| **Mentor** | **শুধু নিজের তত্ত্বাবধানের ইন্টার্ন** দেখা, ছুটির সিদ্ধান্ত ও অনুপস্থিতি চিহ্নিত করা, প্রতিবেদন পর্যালোচনা, মূল্যায়ন জমা (cl.14)। |
| **Admin** | বাকি সব: ওভারভিউ, ব্যাচ ও cl.6 ওভাররাইড, যাচাই, পরীক্ষার নম্বর, নির্বাচন, পদায়ন, সব ইন্টার্ন, বদলী, সমাপ্তি, সনদ, বাতিল, স্লিপসহ ভাতা পরিশোধ, ব্যবহারকারী। |

সিডার এই ডিফল্টগুলো কেবল সেই ভূমিকাকে দেয় যার এখনো কোনো অনুমতি নেই, তাই পরে ডেটাবেসে করা পরিবর্তন কখনো মুছে যায় না। অনুমতি কোডের তালিকা `backend/Nexus.Application/Security/Permissions.cs`-এ।

## ৫. পর্দাসমূহ

### ৫.১ শিক্ষার্থী — `/internship/programme`

| ট্যাব | বিষয়বস্তু |
| --- | --- |
| **Programme** | এক নজরে নীতিমালা, খোলা ব্যাচ, প্রতিটি নিয়মের কারণসহ যোগ্যতার তালিকা, আবেদন ফর্ম (উদ্দেশ্য বিবরণী, সর্বোচ্চ ৩টি পছন্দের বিভাগ)। |
| **My application** | অবস্থা, পরীক্ষার ফল, ইতিহাসের টাইমলাইন, প্রত্যাহার। |
| **My internship** *(Active বা পরে)* | বিভাগ ও মেন্টর, আজকের check-in/out, ৮০% রেখাসহ উপস্থিতি %, সাম্প্রতিক দিন, ছুটির আবেদন, মাসিক প্রতিবেদন ও ভাতা (মাস শেষে প্রতিবেদন জমা, মূল্যায়ন, স্লিপ), চূড়ান্ত প্রতিবেদন ও শেষ তারিখ, মূল্যায়ন, সনদ। |

### ৫.২ Admin ও Mentor — `/internship/manage`

| ট্যাব | কে | বিষয়বস্তু |
| --- | --- | --- |
| **Overview** | Admin | খোলা ব্যাচ, নির্বাচনাধীন প্রার্থী, বাকি আসন, সক্রিয় ইন্টার্ন, উপস্থিতি-ঝুঁকি, "needs action" তালিকা, ফানেল। |
| **Batches** | Admin | তালিকা, তৈরি, অবস্থা পরিবর্তন; cl.6-এর সীমা ছাড়ালে ওভাররাইড ডায়ালগ। |
| **Applications** | Admin | ব্যাচ ও অবস্থা অনুযায়ী ফিল্টার; shortlist, reject, waitlist, পরীক্ষার নম্বর, নির্বাচন (আসন পর্যন্ত), মেন্টরসহ বিভাগে পদায়ন। |
| **Interns** | Admin; Mentor শুধু নিজের ইন্টার্ন | পদায়নের ইতিহাস, বদলী, হাজিরা, ছুটির সিদ্ধান্ত, অনুপস্থিতি চিহ্নিত, প্রতিবেদন পর্যালোচনা, মূল্যায়ন, সমাপ্তি, সনদ বা "Not certified", বাতিল। |
| **Allowance** | Admin | অবস্থা অনুযায়ী মাস, উপস্থিতি, কর্তন ও মূল্যায়নের নম্বর; মূল্যায়িত মাস পরিশোধ ও স্লিপ ইস্যু; শেষ মাসের hold। |

### ৫.৩ Admin — `/internship/users`

ভূমিকাসহ (Admin, Mentor বা Student) ব্যবহারকারী তৈরি, সম্পাদনা, পাসওয়ার্ড রিসেট, সক্রিয় বা নিষ্ক্রিয় করা। মেন্টরের একটি বিভাগ লাগে। শিক্ষার্থীর একাডেমিক তথ্য লাগে (বিশ্ববিদ্যালয়, প্রোগ্রাম, স্তর, বর্ষ, স্নাতক শেষের মাস, পরিচয় যাচাই); যোগ্যতা যাচাই এগুলো পড়ে। নতুন ব্যবহারকারী তালিকার উপরে থাকে।

## ৬. কর্মপ্রবাহ (Workflow)

```
শিক্ষার্থী      Admin (ইউজিসি প্রশাসন)      Mentor (বিভাগ)        Admin (হিসাব শাখা)
  │ যোগ্যতা যাচাই
  │ আবেদন ─────────▶ যাচাই ──▶ Shortlisted / Rejected
  │            ◀──── পরীক্ষার আমন্ত্রণ
  │ পরীক্ষা ────────▶ নম্বর লেখা ──▶ র‍্যাংক
  │            ◀──── Selected (≤ আসন) / Waitlisted
  │                  মেন্টরসহ পদায়ন ──▶ Active
  │ প্রতিদিন check in/out ───────────────▶ ছুটির সিদ্ধান্ত, অনুপস্থিতি চিহ্নিত
  │ মাস শেষে মাসিক প্রতিবেদন ─▶ মেন্টরের মূল্যায়ন (৪ মানদণ্ড) + অনুপস্থিত দিন ─▶ পরিশোধ, স্লিপ
  │ চূড়ান্ত প্রতিবেদন (শেষের ১৫ কর্মদিবসের মধ্যে) ─▶ গ্রহণ / সংশোধন
  │                                       মূল্যায়ন + সুপারিশ
  │                  সমাপ্তি, তারপর সনদ (গ্রেড) অথবা "Not certified"
  │                  শেষ মাসের ভাতা ছাড় ──────────────────▶ পরিশোধ
```

| **১ — ব্রাউজার প্রোটোটাইপ** | `localStorage`-এ ক্লিক করে চালানো ডেমো। | সম্পন্ন, পরে **মুছে ফেলা** |
| **২ — বাস্তব সিস্টেম** | ডেটাবেস, API, JWT লগইন, ডেটাবেস থেকে ভূমিকা ও অনুমতি, অডিট, নোটিফিকেশন, উপরের সব পর্দা, ব্যবহারকারী ব্যবস্থাপনা, ডেমো সিড। | **সম্পন্ন** |
| **৩ — মজবুতকরণ** | `InternshipRules` ও সার্ভিসের স্বয়ংক্রিয় টেস্ট; প্রোডাকশন কনফিগারেশন (গোপন JWT কী, কানেকশন স্ট্রিং, CORS, HTTPS); ইন্টার্ন, হাজিরা ও বিলের CSV এক্সপোর্ট; প্রিন্টযোগ্য সনদ; বাংলা লেবেল; অ্যাক্সেসিবিলিটি পরীক্ষা; ব্যাকআপ। | পরবর্তী |
| **৪ — প্রোডাকশন ফিচার** | কর্তব্য-বিভাজনসহ Admin-কে Administration / Accounts / Commission-এ ভাগ; ফাইল আপলোড (CV, ট্রান্সক্রিপ্ট, প্রতিবেদন); ই-স্বাক্ষর ও QR-যাচাইযোগ্য সনদ PDF; ইউজিসি হিসাব শাখার জন্য পেমেন্ট ফাইল; পরীক্ষা ব্যবস্থা থেকে ইমপোর্ট; বাইরের প্রতিষ্ঠানে পদায়ন (cl.8); পরিচয় যাচাইসহ নিজে নিবন্ধন। | পরে |

## ৯. ডেমো স্ক্রিপ্ট (পর্যালোচনার জন্য)

ব্যাকএন্ড ও ফ্রন্টএন্ড চালু করুন (`backend/README.md` দেখুন), তারপর http://localhost:3000/login খুলুন। সব ডেমো অ্যাকাউন্টের পাসওয়ার্ড: `demo123`।

1. `student@nexus.demo` দিয়ে লগইন → **My UGC Internship** → যোগ্যতা দেখুন → খোলা ব্যাচে **Apply**।
2. লগআউট করে `admin@nexus.demo` দিয়ে লগইন → **UGC Internship → Applications** → Shortlist → পরীক্ষার নম্বর ৮৬ লিখুন → Select।
3. একই ট্যাবে **Place**: "Research" বিভাগ, মেন্টর Dr. Mahfuza Khatun ও শুরুর তারিখ দিন → অবস্থা Active।
4. শিক্ষার্থী হিসেবে ফিরে: **My internship** → check in, ছুটির আবেদন; মাস শেষ হলে মাসিক প্রতিবেদন জমা দিন।
5. `mentor@nexus.demo` দিয়ে লগইন → **My interns** → ছুটি অনুমোদন।
6. শিক্ষার্থী চূড়ান্ত প্রতিবেদন জমা দেয়। মেন্টর তা গ্রহণ করে ও মূল্যায়ন জমা দেয়।
7. Admin ইন্টার্নশিপ সমাপ্ত চিহ্নিত করে সনদ ইস্যু করে; মেন্টর প্রতিটি মাসিক প্রতিবেদন মূল্যায়ন করেন; **Allowance** → পরিশোধ করে স্লিপ খুলুন।
8. শিক্ষার্থী সনদ খুলে দেখে।
9. Admin ২০২৬ সালের তৃতীয় ব্যাচ তৈরির চেষ্টা করে → ওভাররাইড-কারণ না দেওয়া পর্যন্ত আটকে যায়।
