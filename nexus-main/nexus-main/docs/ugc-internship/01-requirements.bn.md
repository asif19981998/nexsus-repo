## ১. উদ্দেশ্য

নীতিমালাটি এমন একটি ইন্টার্নশিপ প্রোগ্রাম নির্ধারণ করে যা **ইউজিসির নিজের ভেতরেই** পরিচালিত হয়। ইউজিসি স্নাতক ও স্নাতকোত্তর শিক্ষার্থীদের নিজ বিভাগে ইন্টার্ন হিসেবে নেয়, মাসিক ভাতা দেয় এবং গ্রেডসহ সনদ প্রদান করে।

Nexus-এ আজ যা আছে তা ভিন্ন: কোম্পানি ইন্টার্ন নেয় এবং ইউজিসি বৃত্তির ৫০% সহ-অর্থায়ন করে। এই দুটিকে গুলিয়ে ফেলা যাবে না। এই দলিলে সংজ্ঞায়িত হয়েছে প্ল্যাটফর্মে **ইউজিসি-আয়োজিত ইন্টার্নশিপ** শুরু থেকে শেষ পর্যন্ত চালাতে Nexus-এ কী লাগবে: ব্যাচ গ্রহণ, নির্বাচন, বিভাগে পদায়ন, উপস্থিতি, ভাতা, মূল্যায়ন ও সনদ।

ব্যবহারকারী, ভূমিকা ও অনুমতি ডেটাবেসে থাকে। Admin প্রত্যেক ব্যবহারকারী তৈরি করে ভূমিকা ঠিক করে দেয়। প্রতিটি ভূমিকার অনুমতি `RolePermissions` টেবিলের সারি, তাই নতুন রিলিজ ছাড়াই বদলানো যায়। পরবর্তী ধাপে Admin-কে Administration, Accounts ও Commission-এ ভাগ করা যাবে (পরিকল্পনা, ধাপ ৪ দেখুন)।

## ৭. অকার্যকরী প্রয়োজনীয়তা (Non-functional)

- **বাস্তব সিস্টেম।** SQL Server ডেটাবেস, ASP.NET Core 8 API, Next.js ফ্রন্টএন্ড। বাস্তব পেমেন্ট, পরীক্ষা সফটওয়্যার বা ই-স্বাক্ষর এখনো নেই।
- **নিরাপত্তা**: JWT লগইন; ASP.NET Identity পাসওয়ার্ড হ্যাশ করে; ৫ বার ভুলে অ্যাকাউন্ট লক; প্রতিটি endpoint অনুমতি যাচাই করে; গোপন তথ্য (JWT কী, কানেকশন স্ট্রিং) কনফিগারেশন বা environment থেকে আসে, কখনো সোর্স কোডে থাকে না।
- **নিয়ম সার্ভারে**: নীতিমালার প্রতিটি যাচাই ও হিসাব API-তে চলে (`InternshipRules.cs`)। ফ্রন্টএন্ড শুধু ফল দেখায় এবং যে কাজ ভূমিকার অনুমতিতে নেই তা লুকায়।
- **পরিবর্তনযোগ্য নীতিমালা**: নীতিমালার সংখ্যা ও তালিকা ডেটাবেসের সারি, তাই ইউজিসির সিদ্ধান্তে কোড বদলাতে হয় না।
- **অনুসরণযোগ্যতা**: অডিটে কে, কী, কোন বস্তু ও বিবরণ লেখা হয়; প্রতিটি আবেদনের অবস্থার ইতিহাস থাকে।
- **স্কিমা পরিবর্তন** EF Core মাইগ্রেশনের মাধ্যমে; API চালু হওয়ার সময় তা প্রয়োগ করে।
- **রেসপনসিভ**: মোবাইল, ট্যাবলেট, ডেস্কটপ।
- **পুনর্ব্যবহার**: বিদ্যমান UI কিট (`@/components/ui`)।
- **অ্যাক্সেসিবিলিটি**: লেবেলযুক্ত কন্ট্রোল, কীবোর্ডে চালানো যায় এমন ডায়ালগ, শুধু রঙ দিয়ে অবস্থা না দেখানো।

## ৯. এই ধাপের বাইরে

- বাস্তব পেমেন্ট বা ব্যাংক সংযোগ, বাস্তব পরীক্ষা সফটওয়্যার, ই-স্বাক্ষর।
- বাইরের প্রতিষ্ঠানে ইন্টার্ন পদায়ন (cl.8 "মনোনীত প্রতিষ্ঠান")।
- কর্মকর্তা ও বিশেষজ্ঞদের সম্মানী পরিশোধ (cl.17) — উল্লেখ আছে, তৈরি হয়নি।
- নীতিমালা সংশোধনের (cl.16) Admin পর্দা। আপাতত পূর্ণ কমিশনের সিদ্ধান্ত সরাসরি `InternshipPolicy` টেবিলে লেখা হয়।
- নিজে নিবন্ধন ও ফাইল আপলোড। Admin ব্যবহারকারী তৈরি করে; নথি একটি নির্দিষ্ট তালিকা।

## ১০. গ্রহণযোগ্যতার মানদণ্ড (Acceptance Criteria)

1. ডেমো শিক্ষার্থী যোগ্যতার তালিকা দেখতে পায় এবং খোলা ব্যাচে আবেদন করতে পারে।
2. দ্বিতীয় আবেদন, বা অযোগ্য শিক্ষার্থীর আবেদন, স্পষ্ট কারণসহ আটকে যায়।
3. Admin shortlist, নম্বর লেখা, নির্বাচন (আসন-সীমা পর্যন্ত), এবং মেন্টরসহ পদায়ন করে সক্রিয় করতে পারে।
4. বছরে তৃতীয় ব্যাচ বা ২১ আসন তৈরি করলে ওভাররাইড-কারণ না দেওয়া পর্যন্ত আটকে যায়; ওভাররাইড দৃশ্যমান ও অডিটেড।
5. সক্রিয় ইন্টার্ন check-in/out করতে ও ছুটি চাইতে পারে; ইন্টার্নের মেন্টর (বা Admin) ছুটি নিষ্পত্তি করতে পারে।
6. মাস শেষে ইন্টার্ন হাজিরা-খাতাসহ মাসিক প্রতিবেদন জমা দেয়; মেন্টর cl.10-এর চারটি মানদণ্ডে মূল্যায়ন করে অনুপস্থিত দিন লেখেন; Admin পরিশোধ করলে স্লিপ তৈরি হয়। চূড়ান্ত প্রতিবেদন গৃহীত না হওয়া পর্যন্ত শেষ মাস "Withheld" দেখায়।
7. উপস্থিতি ৮০%-এর নিচে হলে সতর্কতা আসে এবং সনদ আটকে যায়।
8. প্রতিবেদন গৃহীত + মূল্যায়ন জমা হলে Admin গ্রেডসহ সনদ দিতে পারে; শিক্ষার্থী তা খুলে দেখতে পারে।
9. প্রতিটি ধাপে অডিট এন্ট্রি ও নোটিফিকেশন তৈরি হয়; সব ডেটা ডেটাবেসে থাকে এবং API পুনরায় চালু হলেও থাকে।
10. একজন মেন্টর অন্য মেন্টরের ইন্টার্ন খুলতে পারে না, আর অনুমতি না থাকা ভূমিকা API থেকে 403 পায়।
11. ব্যাকএন্ড build হয়; `npm run lint` ও `npm run build` পাস করে।
